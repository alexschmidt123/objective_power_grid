# Required fair comparison protocol

Status: concrete protocol for subsequent implementation; not an executed experiment. No new training authorized or launched by synchronization.

1. Preserve all current checkpoints, results and source versions. Label the 200-update V3 result as a pilot. Do not extrapolate its timing or EIG to convergence.
2. Separate two questions: matched V2-family continuation and end-to-end comparison with native baselines. Never call unlike actor updates equal compute.
3. For V2-family testing, use one common parent/runtime/replay per seed, the same preparation-data budget, native batch 10,000 with 1,000 new T30 episodes per update, critic 5 and posterior 150 updates per actor update, discount 1, and at least 2,000 new actor updates per arm (2M episodes, 60M observations). Match optimizer-reset policy, target initialization, exploration, replay and learning-rate schedules across arms. Use V2's 200-stage history freeze and 1,800-stage fine-tuning only after implementing equivalent inherited-network trainability in V3; document unavoidable architectural differences. Alternatively, a frozen-backbone routing experiment must freeze the corresponding V2 control and make only that narrower claim.
4. To replicate original V2 final-stage treatment exactly, start at its prepared iteration-14,001 state rather than giving V3 a terminal iteration-16,001 parent without matching the control. Archive initialization hashes and counters. A separate terminal-V2 adaptation study is allowed, clearly labeled and separately budgeted.
5. Train learned routing, uniform routing and each of four fixed-expert policies independently under equal continuation budgets and the same permitted information. Also keep inference-only uniform/single ablations of the learned checkpoint: these answer a different question. Add a stage-only/fixed-prior routing control to test whether history dependence contributes. Account for all arms when reporting search/selection cost.
6. Before launching long jobs, verify prefix masking, no hidden-theta/future-observation leakage, bounds/chronology, gradient participation, single-path isolation and the unchanged native objective. Refactor current no_grad/context buffers deliberately if full fine-tuning is intended; requires_grad alone is insufficient. Test equivalent control initialization. Do not silently redesign the experts during training.
7. For all-method results, retain original DAD/vsOED/RL/ScoreBED native schedules as labeled historical references. Run fully specified native-schedule replicas and separate compute-budget curves on common hardware. Include provider/teacher preparation, score pretraining, all restarts and validation/selection cost. Record generated real episodes, analytic/density evaluations, replay updates, GPU time, peak memory and inference latency separately. Do not declare current historical timings hardware-matched. Preserve native vsOED discount 0.9 and add an explicitly labeled discount-1 objective-matched control if comparing the exact undiscounted objective.
8. Use five independent training lineages, including independently seeded learned providers where end-to-end independence is claimed. Shared fixed providers imply conditional seeds and must be labeled. Save scheduled learning curves on a separate training-validation bank. Use predeclared terminal/checkpoint rules; do not choose checkpoints on the canonical reference bank. The existing canonical bank has already been repeatedly observed, so it cannot be described as an untouched final test.
9. Primary evaluation remains exactly V2/DAD/vsOED: 2,000 cases, 1M contrasts, original uniforms, original scorer and hashes. No silent changes to physics, precision, random numbers or contrast counts. Report paired differences/CIs on identical cases, training-seed variation separately, and multiple-comparison correction for primary claims. Disclose finite-contrast bias/ceiling. Additional independent banks are supplementary and clearly labeled.
10. Success requires positive, replicated learned-minus-uniform and learned-minus-best-independently-trained-single differences, plus improvement over V2 and strong native baselines under declared budget regimes. If these fail, report failure; do not replace the scientific criterion with router weight variance. Also report model-information access and inference cost so any advantage can be attributed to MoE rather than extra providers or compute.

Next implementation should establish matched full-trainability/control initialization and the locked multi-arm runner before any larger training launch. Simply appending 1,800 updates to the current frozen-adapter pilot would leave the central fairness issues unresolved.
